抖音直播自动关闭弹幕和礼物特效 v1.4.4

更新或安装
推荐安装：启用 Tampermonkey 后，打开以下 GitHub Raw 链接，在油猴安装页确认安装，再刷新抖音。
https://raw.githubusercontent.com/primabrucexu/MiniTools/main/DouyinLiveClean/douyin-live-clean.user.js
也可手动安装：Tampermonkey → 添加新脚本 → 粘贴 douyin-live-clean.user.js 全部内容 → Ctrl+S 保存。
旧版首次升级到 1.4.1 时，需要手动替换已有脚本全部内容，或从上述 Raw 链接重新安装一次，才能获得更新地址。
仅保留一个版本启用，避免不同版本相互干扰。

自动更新
脚本的 @updateURL 和 @downloadURL 均指向上述 main 分支 Raw 地址。
在油猴设置中启用脚本更新检查，设置检查间隔（例如每天），并确认该脚本允许检查更新。
也可以手动执行“检查更新”；自动更新按设定周期发生，不会在 GitHub 推送后立即执行。
以后发布新版时，递增脚本头部的 @version 并推送到 main 即可，不必创建 GitHub Release。
只改代码而不增加版本号不会正常触发升级。仅修改 GitHub，不会为本地旧版自动补上更新地址。

功能说明
关闭弹幕、屏蔽礼物特效和最高画质三项互不等待，各自在接口就绪后执行。
网页全屏和收起聊天栏会等待原生 Y 控件出现，再经过一轮 250 毫秒轮询后执行，避免控件初始化时重新展开聊天栏。
没有模拟鼠标点击、悬停或快捷键，也没有隐藏弹幕画布。
1. 弹幕：调用原生 roomStore.setDanmakuSwitch(false)，兼容停止旧版 danmu 插件。
2. 礼物特效：调用原生 giftStore.setEffectSwitchStatus(false)。
   内部 false 表示关闭特效，网页的“屏蔽礼物特效”会显示为开启。
3. 清晰度：调用 player.getPlugin('liveStream').handleChangeQuality(...)。
   选择原生接口实际提供、当前可选的最高档位，包含原画、1440P、蓝光、超清、高清、标清。
   尊重网页已有画质限制；不自动登录，不绕过受限档位。
   等待原生切换回调，并回读当前画质和自动调档状态后才确认成功。
4. 网页全屏并收起聊天栏：调用原生 playerStore.setIsTheaterOn(true)，并用 roomStore.setFoldChatroom(true) 收起聊天栏。
   使用播放器 Y 键对应的网页全屏，保留浏览器标签栏；回读 isTheaterOn 和 foldChatroom 均为 true 后才确认完成。
   已经网页全屏时不重复切换，但仍会收起展开的聊天栏；已经折叠的聊天栏不会被展开。
   遵守网页已有全屏权限；已处于浏览器全屏或画中画模式时，本房间跳过自动进入网页全屏和收起聊天栏。
5. 底部礼物栏：用定向 CSS 隐藏 [data-e2e="living-container"] 内的 #BottomLayout 和 .OperatingBarPluginContainer。
   兼容礼物栏插件直接挂载在左侧布局、没有放入 #BottomLayout 的直播间。
   隐藏整条礼物栏，包括礼物图标、价格、“更多”和充值入口；不模拟鼠标或快捷键。
   普通布局和 Y 网页全屏由页面原有布局填满释放出的空间，不保留底栏占位。

生效范围
- https://live.douyin.com/直播间编号
- https://www.douyin.com/follow/live/直播间编号
支持站内进入直播和换房。聊天消息不删除，可手动展开聊天栏。
礼物栏在支持的直播路径持续隐藏，覆盖延迟加载和换房；离开支持路径后移除隐藏样式。
四项原生设置完成后不持续强制设置；你仍可以手动展开聊天、开启弹幕、特效或降低画质。
手动展开聊天栏后，本房间不会再次强制收起；刷新或换房时重新自动收起。
网页全屏可用原生按钮、Y 或 Esc 退出，退出后本房间不强制恢复。
初始化期间在非输入区域按 Y，或在网页全屏中按 Esc，也会让出网页全屏控制。
刷新、换房或原生播放器实例更换时重新初始化。
接口未就绪时最多等待约 30 秒；某项失败不阻塞其他项，控制台会输出“抖音直播清爽”提示。
实际画质切换仍需等待播放器和网络，无法保证所有视觉效果在同一瞬间完成。

为什么匹配整个 www.douyin.com
主站可能通过 SPA 导航进入关注页直播，油猴不一定重新注入脚本。
因此预先加载脚本，但只有 /follow/live/ 路径会执行操作，普通短视频页不触发设置。

验证与限制
v1.4.4 JavaScript 语法检查及 43 项受控回归测试通过。
覆盖两个入口、前三项互不等待、延迟接口、异步回调、异常隔离、手动设置保留、SPA 换房、
同 store 房间变化、画质限制、重复档位和超时后换房恢复；还包括网页全屏状态回读、
权限限制、其他播放模式保持，以及 Y / Esc 的手动控制边界测试。
包含已全屏时补收起聊天、保留已折叠状态、折叠状态延迟确认、手动展开后保持测试，并验证换房重新收起。
两种入口的受控环境中，网页全屏和收起聊天栏会等待原生控件初始化，不阻塞其他三项。
新增两个入口的独立挂载礼物栏用例，覆盖延迟加载、作用范围、离开路径后恢复及重新进入隐藏。
受控环境的调用时间不是实站测速。

当前公开客户端源码明确暴露 window.__STORE__，并包含 /follow/live/:webRid 路由。
原有 v1.3 三项功能已获得用户实际使用的良好反馈。
真实 Edge 已在 live.douyin.com/494992812876 复现独立挂载礼物栏残留，补充样式后两种布局均隐藏且无留白。
另在未登录的独立 Edge 会话中，通过 Playwright 初始化注入完整 v1.4.4 脚本，在该房间及 live.douyin.com/699394970561 验证：
Y 网页全屏及 Esc 退出后的普通布局均隐藏底栏、无底栏留白，原生设置和播放器控件正常。直播间可能呈现不同挂载结构。
受控测试不等同于关注页实站验证；本轮未覆盖油猴扩展安装、登录会话或 follow/live 真实入口。
自动更新已核对脚本元数据和 Raw 文件，尚未在油猴中实际验证更新流程。
无登录态请求关注页会被重定向，无法证明所有关注页版本均暴露相同全局对象。
这些是抖音内部方法，不是稳定的公开 API。网页改版可能需要更新脚本。
缺少原生接口时不会偷偷退回模拟点击；会等待并报告未完成的项目。

检查方法
刷新进入直播间，查看原生面板：
“弹幕开关”关闭，“屏蔽礼物特效”开启，清晰度为当前可选最高档，且不是自动模式。
满足权限且未处于其他播放模式时，播放器应进入 Y 对应的网页全屏并收起聊天栏，浏览器标签栏仍保留；视频下方的礼物栏应隐藏。
若有一项未生效，可提供完整直播间网址和控制台包含“抖音直播清爽”的提示。
